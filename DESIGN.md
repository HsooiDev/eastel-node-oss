# Design System: Eastel Mobile

## Overview

This file contains two scoped visual systems. Unprefixed frontmatter tokens and the **Public website** guidance preserve the established consumer website. Tokens beginning `admin-` and the **Cobalt admin workspace** guidance apply only inside the admin shell and admin sign-in. The admin choice does not replace the public identity. Token values come from the incumbent public document and implemented admin CSS; this document does not certify runtime or visual QA.

### Public website

**Creative North Star: "The Telco Dashboard"**

Eastel's visual system works like a well-designed control panel: data-rich but calm, information-first, decoration-last. Every element earns its place by serving a transaction — comparing plans, finding a price, clicking "Buy Now." The aesthetic is Swiss-clarity applied to Malaysian mobile: clean grids, confident typography, one accent color used with restraint.

This is not a lifestyle brand. It's not a tech startup. It's a utility interface for phone plans. The design rejects AI-generated SaaS templates (glassmorphism, gradient text, hero metrics, identical card grids) and big-telco corporate clichés (stock photos, red branding, cluttered mega-menus). It finds its voice in functional honesty: real prices at real sizes, real certificates shown prominently, real contrast for real readability.

The single-family Manrope typography (variable, 200–800 weight range) carries the entire hierarchy through weight contrast alone. Electric blue (#0066FF) is the sole accent — used on primary buttons, active states, and section kickers, never as decoration. Surfaces are flat at rest and lift on interaction, creating a tactile, responsive feel without visual noise.

**Key Characteristics:**
- Single accent, single font family, single purpose per page
- Flat surfaces lift only on hover/focus — shadow is feedback, not decoration
- Dark and light themes with equal design attention
- Information hierarchy through scale + weight, not color + decoration
- Multilingual (EN, BM, ZH) with equal visual quality across all three

### Cobalt admin workspace

**Creative North Star: "Cobalt Grid"**

A decisive cobalt navigation plane and precisely aligned work areas make Eastel's admin feel like one operational product. Pale cool canvas, white work surfaces, navy ink and restrained line icons establish clear locations for navigation, records and actions. The user selected this world for every admin page with equal attention to desktop and phone.

Visual authority follows the user's instruction: “以实际预览为准，效果图只作视觉参考（建议）” — the actual preview is authoritative; the mockup is visual reference and advice. Implemented responsive values below describe the current interface. A difference from the mockup is not by itself a defect, and this authority choice does not certify QA or close workflow gates.

Compact work surfaces use readable labels, visible focus and reachable controls. Open figures communicate store totals without decorative metric pills. Active navigation becomes a white inset in the cobalt plane; the phone menu moves in from the edge. The interface is semantic code. Generated marketing artwork remains a separate output inside its preview, rather than becoming the visual authority for the surrounding tools.

**Key Characteristics:**
- A stable cobalt navigation plane and flat, bordered work surfaces
- Self-hosted Inter Tight for the interface and Funnel Sans for store figures
- Equal desktop and phone priority, with labeled records and reachable quick navigation
- Light and dark work surfaces, with the cobalt rail retained in both themes
- Semantic controls and native modal interaction

## Colors

### Public website

The palette is built around one committed accent (electric blue) and a full neutral ramp that works in both light and dark themes. No secondary or tertiary accent colors exist — the restraint is intentional.

### Primary
- **Electric Blue** (#0066FF): The sole accent. Used on primary buttons, active navigation states, section kickers, focus rings, and the "Popular" plan card. Covers roughly 5-8% of any given surface. In dark theme, shifts lighter to #3388FF for equivalent perceived brightness.

### Neutral
- **Surface White** (#FFFFFF): Card backgrounds, input fields, modal containers. The default canvas for content in light theme. Dark theme: #0D1117.
- **Surface Off-White** (#F5F7FA): Alternating section backgrounds, hover states on light surfaces, secondary card areas. Dark theme: #131820.
- **Surface Hover** (#EBEFF5): Row hover, selected list items, active filters. Dark theme: #1A2030.
- **Foreground Near-Black** (#0D1117): Body text, headings, icons, primary information. High contrast against Surface White (16.1:1). Dark theme: #ECEEF2.
- **Foreground Muted** (#5A5F6B): Secondary text, captions, placeholder text, inactive navigation. Dark theme: #8892A0.
- **Border Pale** (#E2E5EB): Card borders, input strokes, table dividers, section separators. Dark theme: #242C38.
- **Background Warm** (#F8F9FB): Page background behind all surfaces. Slightly tinted off-white. Dark theme: #090C12.

### Named Rules
**The One Accent Rule.** Electric blue is the only accent color on any surface. No secondary accent, no tertiary, no decorative color. If it's not blue, it's a neutral. Chips and tags use tinted blue backgrounds, never a second hue.

**The Contrast Guarantee Rule.** All body text on Surface White must exceed 7:1 contrast. All text on Electric Blue must exceed 4.5:1. Muted text on backgrounds may use 3:1 minimum.

Dark-theme pairs are separately implemented.

**The Scoped Palette Rule.** The public One Accent Rule remains a public rule. Use the admin palette inside admin chrome; do not impose either palette on generated artwork marked as a preview.

## Typography

### Public website

**Font:** Manrope (variable, 200–800 weight range)
**Character:** A warm geometric sans with open apertures and a modern x-height. Friendly enough for Malaysian consumers, technical enough for plan comparison tables. Single family carries all roles through weight and scale alone — no display/body pairing needed.

### Hierarchy
- **Display** (800, clamp(2.5rem, 5vw, 5rem), line-height 1): Hero headlines only. Used once per page. The heaviest weight, tightest leading, tightest tracking.
- **Headline** (700, clamp(2rem, 3.5vw, 3.5rem), line-height 1.1): Section headings (H2). Bold but not shouting. Used 4-6 times per page.
- **Body** (450, 1rem/16px, line-height 1.6): All body text, plan descriptions, feature lists. Comfortable reading size with generous leading. Maximum line length capped at 65ch via container widths.
- **Label** (600, 0.75rem/12px, letter-spacing 0.05em, uppercase): Section kickers, form labels, badge text, navigation items. Small but legible. The only uppercase role.

### Named Rules
**The Weight-Only Rule.** Hierarchy is expressed through font-weight and scale only. No color changes, no italic, no decoration on headings. The single-family constraint forces weight discipline.

**The 65ch Rule.** Body text containers never exceed 65 characters per line. Paragraphs wider than this are split or capped.

Both use font-display swap. Public Manrope remains the public family.

**Character:** Inter Tight supplies a compact, decisive interface voice; Funnel Sans distinguishes store figures without decorative imagery. The shell uses tabular numerals. Interface labels use normal case and normal tracking; tight negative tracking is reserved for large headings and figures.

- **Overview title:** `admin-wide-overview-title` at (1280px) and above, `admin-overview-title` from (640px) through (1279px), and `admin-phone-title` below (640px). The wide desktop title is (48px); the narrower/base title remains (40px). The direction board's earlier (34px) is reference only.

- **Body / navigation / label / badge:** `admin-body`, `admin-nav`, `admin-label`, `admin-badge` remain the base interface roles. Sidebar route links use `admin-wide-nav` only at (1280px) and above. The base table body uses the navigation size with regular weight and the label role for headers. Wide recent orders use `admin-wide-overview-body`, `admin-wide-table-header` and `admin-wide-order-badge`; work links and the panel action use the wide Overview body size. This is a dashboard specialization, not a new size for every record table.

**The Separate Type Authority Rule.** Inter Tight and Funnel Sans are approved admin families. They do not weaken the public single-family Manrope rule or make artwork fonts into interface fonts.

## Elevation & Depth

### Public website

Surfaces are flat at rest. Depth is conveyed through background color alternation (Background → Surface Alt → Surface). Shadows appear only as interactive feedback: a card lifts 1px with a soft shadow on hover, a button gains a blue-tinted glow on hover. No element ships a permanent shadow.

### Shadow Vocabulary
- **Hover Lift** (`box-shadow: 0 10px 25px -5px rgba(0,102,255,0.08), 0 4px 10px -6px rgba(0,0,0,0.05)`): Card hover, button hover. Paired with `translateY(-1px)` for the lift effect.
- **Active Press** (`box-shadow: none; transform: translateY(0)`): Button press. The lift reverses; the element returns to flat.
- **Popular Glow** (`box-shadow: 0 0 30px rgba(0,102,255,0.15)`): The featured/highlighted plan card. A soft, wide glow in accent blue — the only permanent shadow in the system, and it's a glow, not a drop shadow.

### Named Rules
**The Flat-By-Default Rule.** No element ships a permanent drop shadow. Shadows are reserved for interaction (hover, focus, active) and exactly one marketing highlight (the Popular plan card glow). If something looks elevated without being interacted with, it's wrong.

### Cobalt admin workspace

Admin cards and primary actions explicitly remove decorative shadows. Canvas/surface/soft layers, thin boundaries, inset navigation and the native dialog top layer provide depth. Dialog and drawer backdrops use `rgb(10 24 50 / 55%)`. Work-surface focus uses a (2px) cobalt outline at a (3px) offset; cobalt-plane links and buttons switch to a white outline. Drawer entry moves from translateX(28px) to zero over (180ms ease-out); navigation background/color and group chevrons transition over (160ms). Reduced-motion preferences disable shell animation and transition. The admin's flat resting surfaces do not inherit the public card lift.

## Components

### Public website

### Buttons
**Character:** Tactile and responsive. Buttons feel like real things you press — they lift on hover, press down on click, and glow with accent tint.

- **Shape:** Fully rounded corners (12px radius, `rounded-xl`).
- **Primary:** Electric Blue background, white text, 16px vertical × 32px horizontal padding. Semibold (600) weight. Hover: shifts to Electric Blue Light, gains shadow glow with blue tint, lifts 0.5px. Focus: 2px blue outline at 2px offset.

- **Size variants:** Default (py-4 px-8, 16px/32px) and compact (py-2.5 px-5, 10px/20px for plan cards, mobile CTAs).

### Cards
**Character:** Clean containers that group related information. Flat at rest, subtle lift on hover.

- **Corner Style:** Strongly rounded (16px radius, `rounded-2xl`).

- **Internal Padding:** 28px (p-7) for feature cards, 24px (p-6) for plan cards.
- **Hover:** Border shifts to Electric Blue at 30% opacity. Gains Hover Lift shadow. Translates up 1px. Duration: 300ms, ease-out-expo.

## Do's and Don'ts

### Public website

### Do:
- **Do** use Electric Blue (#0066FF) exclusively as the accent — one color, one voice
- **Do** express hierarchy through font weight (200–800) and scale (clamp-based fluid headings)
- **Do** keep surfaces flat at rest — shadows only on hover, focus, or the single Popular plan card
- **Do** use 12px–16px border radii on interactive elements (buttons, cards, inputs)
- **Do** maintain ≥44×44px touch targets for all interactive elements on mobile
- **Do** use the Surface Alt (#F5F7FA) background to differentiate adjacent sections without borders
- **Do** show real prices, real data caps, real certificate images — trust through transparency

### Don't:
- **Don't** introduce a second accent color — no green, no purple, no orange. The One Accent Rule is absolute
- **Don't** use gradient text (`background-clip: text`) anywhere — emphasis comes from weight and size
- **Don't** use glassmorphism as decoration — the header backdrop-blur is functional for scroll context, not aesthetic
- **Don't** add permanent drop shadows to cards or containers — shadows are interactive feedback only
- **Don't** use side-stripe borders (`border-left`/`border-right` > 1px) as colored accents on cards or callouts
- **Don't** ship hero-metric stat pills (big number + small label in rounded rectangles) — use inline text with pipe separators
- **Don't** use identical icon-heading-description card grids — alternate layouts, vary visual weight, or break grids intentionally
- **Don't** use display serif fonts, italic drop caps, numbered sections, or ruled separators — this is a telco dashboard, not a literary magazine
- **Don't** use stock photos of people smiling at phones or generic "diverse customer" imagery
- **Don't** add a fourth font weight role — Display (800), Headline (700), Body (450), Label (600) is the complete set

### Cobalt admin workspace — Do:
- **Do** use Cobalt Grid only inside the admin shell and admin sign-in, preserving the public site's established identity.
- **Do** use the self-hosted Eastel Admin interface family and Eastel Figures for store figures.
- **Do** keep the cobalt plane, white active inset, cool work surfaces and flat bordered panels coherent across every admin page.
- **Do** give desktop and phone equal priority, with visible focus, reachable controls and full route access.
- **Do** retain data labels, totals, payment and fulfilment states when tables adapt on phone.
- **Do** keep native modal dismissal rules and existing loading, disabled and error behavior.
- **Do** preserve generated artwork inside its scoped preview while styling surrounding controls as admin UI.
- **Do** use the actual preview as visual authority and treat mockups as reference and advice, preserving each implemented responsive range.

### Cobalt admin workspace — Don't:
- **Don't** export admin fonts, status hues or geometry into the public website.
- **Don't** use artwork styling as authority for interface chrome.
- **Don't** add decorative gradient text, glass cards, metric pills or permanent card shadows to the admin UI.
- **Don't** erase semantic status text or task actions to obtain a cleaner screenshot.
- **Don't** treat the provisional direction-board title size, sidecar sample values or a documented token as acceptance evidence.
- **Don't** call the separate automated build-phase workflow complete or pixel fidelity passed while its hero and remaining gates are open. The owner-approved actual-preview criterion must be recorded separately.
